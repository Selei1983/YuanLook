# 设备 IP 与访问延时

设备监控页的卡片、桌面表格及手机卡片，在服务器名称下显示 IP 和访问延时。

- IP 优先展示已采集的公网 IPv4 / IPv6；都没有时显示探针连接来源 IP。经过 NAT 或反向代理时，来源 IP 不一定是设备的直连地址。
- 访问延时是 **面板服务器 → 设备 IP** 的 ICMP 平均往返时间，不是浏览器到设备的延时，也不是网站响应时间。优先检测 IPv4，其次 IPv6，再次连接来源 IP。
- 每台启用设备每 6 小时检测一次，约每天 4 次；一次发送 3 个 Ping 包，整体超时不超过 5 秒。首次发现设备时开始检测。
- 最新结果和检测时间写入各账号独立 SQLite 数据库的 `agent_access_checks` 表。刷新页面、探针重连、面板重启都不会额外触发检测。失败也遵循同一间隔。
- 页面显示毫秒数、上次检测时间、待检测、未响应或检测失败；超过 7 小时的结果标记为待更新。IP 改变后不把旧 IP 的结果当作新 IP 的延时。
- 未响应也可能是设备屏蔽 ICMP，不改变设备在线状态，不触发现有服务告警。已禁用设备不检测；离线但启用的设备仍按低频检测。
- 不修改原有“服务监控”任务频率，也不需要更新探针程序。

面板优先使用非特权 ICMP socket；环境不支持时尝试已有的 raw ICMP 权限。没有权限会显示检测失败，不会自动修改系统权限。测试仅接受 IP 字面量，拒绝回环、链路本地、组播和未指定地址；允许已登记设备的内网 IP。

## 构建与上线

继续使用 `make build-web` 或 `make build-default-theme`。构建脚本在临时目录中读取 `.github/default-theme.ref` 锁定的主题，并应用 `patches/default-theme-device-access.patch`，确保从 YuanLook 仓库重建也包含这次界面变更，无需修改上游仓库。升级主题版本时需要检查补丁能否应用。

上线需更新服务端二进制和 `themes/default` 构建产物；启动时自动创建检测结果表。不会修改既有指标或服务监控配置。IP 和延时仍受现有登录及工作区隔离保护。
